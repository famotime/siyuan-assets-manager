## 1. 特性概述与设计目标

### 1.1 传统图片编辑痛点
在思源笔记生态中，图片一旦经过标注工具（如箭头、文本、框选）编辑并导出：
- 画布会被“烘焙（Bake）”压平成一张位图图片（PNG/JPG）写入 `data/assets/`；
- 所有历史标注元素与像素完全固化，无法单独移动、修改文案、调整样式或撤销删除；
- 再次编辑时只能在已有脏痕迹上叠画，或者必须重新上传无标注的原图从头制作。

### 1.2 核心设计目标与改进策略
`siyuan-assets-manager` 实现了**非破坏性、可交互且解耦的二次编辑架构**：
1. **轻量矢量图层分离**：不使用原图 PNG `tEXt` 块塞入 Base64（避免导致图片文件体积膨胀数倍或被压缩工具损毁），仅提取纯标注矢量图层（Fabric.js Canvas 对象）。
2. **Sidecar 独立元数据（真理源）**：以资产文件为核心，将二次编辑元数据保存在插件专属目录中的独立 JSON 文件（`data/storage/petal/siyuan-assets-manager/metadata/${assetName}.json`），彻底解耦单点块生命周期。
3. **块属性向前兼容与即时自愈（Self-Healing）**：保留思源块自定义属性（`custom-asset-reedit`），在读取和全库扫描时自动双向同步与自愈迁移。
4. **原始干净底图隔离存储**：将未修改的初始底图保存在插件隔离目录（`data/storage/petal/siyuan-assets-manager/originals/`），避免思源原生“清理未引用资源”误删底图，并确保二次编辑时底图清晰无重影。
5. **拓扑关联与防连带误删**：资源管家将原始底图与前端渲染图、文档引用建立拓扑图，只要渲染图仍有有效引用，原始底图绝不被判定为孤立文件。
6. **全生命周期深度协同**：在资源重命名、去重归一化合并及文档引用改写过程中，自动同步维护二次编辑元数据。

## 3. 核心数据模型与规范

### 3.1 块自定义属性与存储路径规范

- **思源块自定义属性名**：`custom-asset-reedit`（定义于 [`src/utils/siyuan-block.ts::CUSTOM_ATTR_REEDIT`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/siyuan-block.ts#L13)）。
- **Sidecar 元数据存储路径**：`data/storage/petal/siyuan-assets-manager/metadata/${assetName}.json`。
- **原始底图隔离存储路径**：`data/storage/petal/siyuan-assets-manager/originals/${timestamp}_${baseName}`。

### 3.2 元数据接口规范 ([`src/types/reedit.d.ts`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/types/reedit.d.ts))

```typescript
export interface IAssetReEditMetadata {
  /** 元数据协议版本号，当前为 1 */
  version: number;
  /** 插件隔离存储目录中的原始底图相对路径，如 originals/172000_foo.png */
  originalStoragePath: string;
  /** 原始底图的 Hash 校验（可选，用于一致性比对） */
  originalHash?: string;
  /** 当前渲染输出并插入文档的 assets 资源文件名（如 foo-edited-20261002.png） */
  renderedAssetName: string;
  /** 标注所在的原始画布/图片物理尺寸 */
  canvasSize: {
    width: number;
    height: number;
  };
  /** 是否使用了 lz-string 算法编码压缩 */
  compressed: boolean;
  /** 
   * 矢量图层载荷
   * - compressed 为 false: { objects: any[], version?: string }
   * - compressed 为 true: lz-string 编码紧凑字符串
   * 严禁包含底图 Base64，仅记录纯矢量交互元素
   */
  vectorData: any | string;
  /** 最后更新时间戳 (ms) */
  updatedAt: number;
}
```

### 3.3 阈值自适应压缩与容错机制 ([`src/utils/reedit-data.ts`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/reedit-data.ts))

1. **体积自适应压缩**：
   - 阈值常量 `COMPRESSION_THRESHOLD_BYTES = 2048` (2KB)；
   - 序列化时若矢量数据体积 `< 2KB`，采用标准 JSON 存储（`compressed: false`），保持易读性；
   - 若体积 `>= 2KB`，使用 `lz-string` 的 `compressToEncodedURIComponent` 压缩（`compressed: true`），体积可减少 60%~75%，大幅减轻思源 SQLite 存储开销。
2. **HTML 实体容错解码**：
   - 思源内核在写入和读出块 IAL 属性时可能将引号等特殊字符转义为 `&quot;`、`&#123;` 等 HTML 实体；
   - [`decodeHtmlEntities`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/reedit-data.ts#L11) 在反序列化时自动递归清理所有形式的实体字符，杜绝因格式转义导致的解析崩溃。

## 4. 关键技术实现机制

### 4.1 TUI Image Editor 与 Fabric.js 矢量桥接 ([`src/utils/tui-image-editor-bridge.ts`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/tui-image-editor-bridge.ts))

- **纯矢量提取（Serialization）**：
  [`extractVectorDataFromTui`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/tui-image-editor-bridge.ts) 获取 TUI 内部封装的 Fabric Canvas，排除 `backgroundImage`（确保底图二进制绝不膨胀到元数据中），完整提取图层关键属性（坐标、尺寸、边框、填充色、字体、字号、箭头类型、不透明度等）。
- **矢量反序列化注入（Deserialization）**：
  [`applyVectorDataToTui`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/tui-image-editor-bridge.ts) 清空画布中原有的残留标注，通过 `fabric.util.enlivenObjects` 批量实例化所有矢量对象，并为每个对象重新附加选框控件与事件监听器（`selectable: true`, `evented: true`, `hasControls: true`），恢复全功能交互。

### 4.2 原始底图安全隔离与存储抽象 ([`src/utils/file-system.ts`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/file-system.ts))

- 底层由统一存储抽象层驱动（Electron 环境使用原生快速文件系统，Web/移动端通过思源 HTTP API 适配，支持系统回收站 `isTrashSupported`）。
- **底图安全归档**：
  首次编辑时通过 [`saveOriginalImage`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/file-system.ts#L111) 将干净底图写入 `storage/.../originals/`；后续再次编辑时直接复用既有底图路径，绝不重复生成冗余底图。
- **底图安全读取**：
  通过 [`readOriginalImage`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/file-system.ts#L118) 读取；若隔离底图由于外部清理不可用，编辑器提供安全降级机制，自动回退到当前 assets 图片作为底图。

### 4.3 编辑保存工作流 ([`src/utils/asset-workflow.ts::executeSaveEditedAssetWorkflow`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/asset-workflow.ts#L73))

编辑保存时由工作流服务统一编排执行：
1. **生成并写入新资源**：基于时间戳或增量规则生成新资源名，写入 `data/assets/`；
2. **融合并发引用**：结合数据库检索到的引用列表与前端传入的目标 `blockId`，规避思源内核 SQLite 异步队列落盘时延导致漏更新的问题；
3. **全场景原子替换**：调用 [`replaceAssetInBlocks`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/siyuan-block.ts#L85)，同步更新 Markdown 正文、根块封面图 IAL（`title-img`）以及属性视图（AV）引用；
4. **Sidecar 与块属性双写**：同步持久化 Sidecar JSON，并在关联块上写入 `custom-asset-reedit`；
5. **旧资源安全替换与清理**：根据用户设置提示并清理旧的衍生资源文件及其过期的 Sidecar 元数据。

### 4.4 宿主隔离与快捷键防护 ([`src/utils/host-isolation.ts`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/host-isolation.ts))

- **快捷键作用域隔离**：在 [`ImageEditorDialog.vue`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/components/ImageEditorDialog.vue#L114) 中捕获全局键盘事件。对撤销（Ctrl/Cmd+Z）、重做、退出（Esc）等快捷键进行严格拦截与重定向，彻底阻止事件冒泡至思源笔记主窗口，防止误触思源文档的撤销/重做或面板关闭。
- **视图伪影清理与滚动锁定**：弹窗挂载时调用 `lockHostScroll()` 阻止宿主文档滚动，并在打开/关闭时调用 `cleanTuiSvgArtifacts()` 与 `resetHostViewport()`，彻底清理 TUI 生成的离屏 SVG 标记，避免污染思源 DOM 树。

## 5. 资源管家面板与生命周期深度集成

### 5.1 界面识别与多维筛选
- **状态徽标**：在卡片列表与紧凑表格中，所有携带二次编辑元数据的资源均带有醒目的 `[可二次编辑]`（或调色盘图标）徽标。
- **类型过滤**：资源管家顶部筛选器支持切换至“可二次编辑”视图（`reeditable`），便于一览全库所有保留矢量状态的图表与标注图片。

### 5.2 拓扑目录与防连带误删保护 ([`src/utils/asset-catalog.ts`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/asset-catalog.ts))
在目录拓扑构建函数 `buildCatalogTopology` 中：
- 将物理资产、SQL 引用、Sidecar 元数据、块级 IAL 以及 `originals/` 目录进行多维融合；
- **防连带误删算法**：原始底图的有效引用计数不仅来源于块属性，还直接追溯绑定到其渲染图片（`renderedAssetName`）。只要渲染图片仍被任何一篇文档引用，其对应的原始底图就被视为受保护资源，绝不会被误判定为“未引用资源”或“孤立底图”。
- **孤立底图清理**：仅当文档块和渲染图片均已被彻底物理删除时，无主底图才会被标记为 `orphanOriginals`，支持在资源管家中一键安全清理。

### 5.3 重命名与去重协同
- **资源重命名**：重命名已编辑图片时，自动同步改写 Sidecar 中的 `renderedAssetName` 以及文档块的 IAL 属性。
- **去重归一化合并**：在 [`dedup-normalize.ts`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/utils/dedup-normalize.ts#L76-L94) 中，当重复组中的主保留资源包含二次编辑元数据时，会自动同步其 Sidecar 文件并注入目标引用块，确保合并后二次编辑能力完好无损。

## 6. 前端编辑器交互与控制规范 ([`ImageEditorDialog.vue`](file:///d:/MyCodingProjects/siyuan-assets-manager/src/components/ImageEditorDialog.vue))

| 交互场景 | 触发方式 | 行为表现与技术保障 |
| :--- | :--- | :--- |
| **文档内右键编辑** | 在思源文档图片块上右键 -> `资源管家 - 编辑标注` | 自动获取当前块 `blockId`，优先检索 Sidecar，随后回退至块属性；命中后自动进入“二次编辑模式”，载入干净底图并恢复矢量图层。 |
| **资源管家内编辑** | 在资源管家列表/卡片中点击“编辑”按钮 | 自动根据资产名称索引 Sidecar 与关联引用块，自动识别是否为可二次编辑资源。 |
| **二次编辑模式标识** | 进入编辑器后标题栏显示 | 顶部标题展示 `编辑图片: foo.png` 以及蓝色徽标 `二次编辑模式`（悬浮提示：`当前处于二次编辑模式，图层为可交互矢量状态`）。 |
| **重置为原始底图** | 标题栏重置按钮 (`RotateCcw`) | 二次确认弹窗（防误触）；确认后清空画布上的所有矢量标注并重新居中原始干净底图。 |
| **合并固化图层** | 标题栏图层按钮 (`Layers`) | 二次确认弹窗；确认后移除该块与该资源的二次编辑元数据，本次及后续保存将作为普通位图处理，降级为常规图片。 |
| **本地另存** | 底部“另存”按钮 (`Download`) | 将当前编辑中的全分辨率画布直接导出并下载至用户本地磁盘，不影响思源文档与资产库。 |
| **保存并同步** | 底部“保存”按钮 (`Check`) | 执行工作流：导出高清位图、更新 assets、原子更新引用块、维护 Sidecar、提供成功消息通知。 |
